# OPD teacher replacement: 35B versus 397B

Status: completed,2026-09-14 (America/Los_Angeles). The experiment was registered in
[STRONG_TEACHER_PLAN.md](STRONG_TEACHER_PLAN.md) before paid execution.

The397B teacher did not outperform35B on this table task, and replacing it in
pure OPD did not improve the student. Test Cell F1 changed0.4575→0.4342 with an
interval including zero, while format/truncation reliability deteriorated.
All four operations completed for an incremental token-based estimate of
**$3.9671**,37.7 operation minutes, below the$10 ceiling. These are not supplier
invoice amounts or the total coding/analysis time.

The treatment changes only the teacher identity in the existing H2 recipe:
Qwen3.6-35B-A3B → Qwen3.5-397B-A17B (64K). The student starts from the same
Qwen3.5-4B Base with fresh rank8 LoRA, fixed Train160,20 updates, LR3e-5 and two
warmup steps. It uses pure sampled reverse-KL OPD, with no gold-CE training branch.
Full gold Train32/Dev100 likelihood measurements remain diagnostic only.

## Comparison protocol

The reused H2 control has Test Cell F1 0.4575, numeric F1 0.5162, format pass97%
and truncation2%. Its completed training and Test W&B records were read back and
matched against local configurations, metrics and histories before this run.

Tokenizer identity and serialized multimodal prompts matched for all160 training
images before paid execution. The397B processor revision is
`8472618112abcbd45acbcdc58436aff4233c23f7`; both models use the same pinned cookbook
and non-thinking renderer. Hosted weight revisions are not exposed by Tinker.

Teacher Dev100 generation uses seed20260913 to match the old teacher evaluation.
Student Dev100 uses seed20260914 and Test100 uses20260913, matching H2. The final
step20 is selected in advance. Cell F1 is primary, with paired10,000-resample
bootstrap intervals, seed20260914, and format/truncation checks. All secondary
metrics and denominators are retained.

The fixed-prefix diagnostic selects32 existing H2 rollouts in original training
order, from optimizer-before steps0–3. Only the first8 were generated by the
untrained Base student. Both teachers score identical prompts and token sequences;
these historical trajectories are never used for training the new student.

its settings, and describe it as a teacher replacement rather than confirmed
stronger-teacher supervision.

paired100-image intervals do not account for this or repeated-training variance.

## What this experiment teaches

The presumed stronger-teacher intervention was not established:397B itself had
worse numeric/structure quality on matched Dev100. Student content gains were
not established, reliability worsened, and gold likelihood worsened on both Train
and Dev despite smaller update-k3. This does not show that a genuinely better task
teacher would fail, that4B lacks capacity, or that increasing teacher size generally
harms OPD. It supports evaluating task-specific teacher quality before spending
more on scale, and retaining35B H2 as the current pure-OPD reference. No additional
training, teacher search or hyperparameter sweep was run after these results.

## Reproduction and evidence

Final verification: **357 local tests passed** (two dependency deprecation
warnings). Independent audits re-scored both teacher Dev sets, both new student
Dev checkpoints and matched Test100 outputs; all metrics matched. They verified
160 original student trajectories,20 updates,five diagnostics, all gold likelihood
targets and masks, and all four receipt hashes/costs. No implementation or
accounting defect was identified by these checks.

W&B readback verified6/6 runs: two reused H2 controls plus four new training,
teacher, prefix-probe and Test runs. New training has58 matching configuration
fields,94 summary metrics,20 updates andfive diagnostics; new Test has25 matching
configuration fields and16 metrics. The shared group containsnine finished Test
runs, with the new ID/label exactly once. All checked runs contain only expected
files and no raw-data artifacts.

Teacher selection, revision and uncached rates are explicit in `teacher_config.py`.
`teacher_eval.py` validates the full Dev manifest and records gold likelihood plus
free generation; `teacher_probe.py` compares teacher feedback on fixed saved
trajectories. `opd.py --teacher-model Qwen/Qwen3.5-397B-A17B` preserves the H2
training recipe. Checkpoint evaluation/publication use the existing entry points.
All input/output/credential locations are CLI arguments.

The local campaign keeps commands, complete run reports, predictions, likelihoods,
rollouts, per-request budgets, hashed operation receipts and an aggregate comparison
index under an ignored output directory. Raw data, local paths, credentials and
checkpoint addresses are not committed or uploaded to W&B. W&B receives explicitly
allowlisted configuration and aggregate metrics; Tinker receives authorized model
inputs for inference/training.
Hosted training checkpoints have a seven-day TTL. Saved predictions, likelihoods,
configuration and comparison records remain usable for future comparisons without
requiring the checkpoint to remain available.

## Interpretation limits

This is a single-seed, Train160 replacement experiment with a historical H2 control
and a repeatedly used Test100. Teacher identity also changes pretraining and
architecture; it does not isolate parameter count. Different on-policy trajectories
are an expected consequence of training. Cross-teacher KL magnitudes are not
quality rankings, and teacher generation quality is not a strict student upper
bound. Do not infer Train800 performance or universal teacher-size effects.
