# OPD 四个假设：实验结果与诊断

实验日期：2026-09-14（America/Los_Angeles）。四个假设、四组Train160及全部评估已完成。
预登记设置和判定规则见 [OPD_HYPOTHESES.md](OPD_HYPOTHESES.md)。

本轮支持降低学习率（H2）和加入真实标签CE（H4）；没有发现更早的OPD800 checkpoint
更好（H1），Top10配方（H3）则出现明显重复/截断退步。新增计算费估算 **$6.4548**，
11项顺序操作累计105.2分钟，低于$10授权上限；不包含历史OPD800费用或本地开发分析时间。

## 比较范围

H1 复用原 OPD800 的 step25/50/75/100。H2–H4 使用一个新 Control160：四组均取
固定 Train800 清单的前160张图片，从同一4B Base新建 rank8 LoRA，1 epoch、batch8、
20次更新、2步线性warmup，固定相同 seed、数据顺序和生成长度限制。
这四组的训练图片数和更新次数相同；不能把它们与 KD800/OPD800 当作等训练量比较。

| 组别 | 唯一预定处理 |
| --- | --- |
| Control160 | 采样 reverse-KL OPD，LR1e-4 |
| H2 | 同一目标，LR3e-5 |
| H3 | 当前 student 前缀上的 teacher Top10 归一化 CE，LR1e-4 |
| H4 | 0.75 OPD token-mean loss +0.25真实标签 token-mean CE，LR1e-4 |

H3 同时改变 KL 方向和估计器，不能把效果只归因于“分布信息更多”。H4 是混合目标，
不是纯 OPD；loss 权重也不等于梯度贡献比例。两次 backward 累积后只调用一次 optimizer。
训练中在0/10/20步测固定 Train32 的真实标签 NLL/PPL 与完整 Dev100 NLL/PPL，
第10/20步各生成完整 Dev100。四组最终 step20 都执行固定 Test100，不按 Test 改参数。
H1 的 Dev seed 为20260914；固定 Test 使用既有20260913协议。

配对差值均按相同图片对齐，10,000次 bootstrap，seed20260914。单元格 F1 是主要
生成指标；数字、整表、结构、RD相似度和格式/截断一起报告。数字/原版RD的缺失值使用
配对完整样本并报告分母，不把无数字表或评分异常当作0。区间只描述这个固定模型对在
样本层面的不确定性，没有覆盖重复训练、托管推理非确定性或多重比较。

## 新日志能说明什么

| 分组 | 记录内容 | 解释边界 |
| --- | --- | --- |
| `training` | sampled KL、teacher NLL、采样熵、目标loss、rollout质量、学习率 | 三个概率指标存在代数关系，不是三条独立证据；每步轨迹和图片会变化 |
| `train` / `dev` | 固定真实标签NLL/PPL；完整Dev生成质量 | 训练probe只有32张；低NLL不保证自由生成正确 |
| `optimizer` | API返回的未裁剪梯度范数、可用性、超过阈值1的标志 | 超阈值标志是派生量，不是服务端返回的裁剪率 |
| `opd_diagnostics` | advantage分布、近零比例、信号集中度、ESS、更新前后概率、类别/失败轨迹占比 | 信号是标量surrogate代理，不是参数梯度归因 |
| `runtime` | 实际token计数、步骤耗时、计算费估算 | 按记录用量和单价估算，不是供应商账单 |

advantage与 |ratio×advantage| 在所有组都按采样reverse-KL计算。对H3，它们只是
同一student轨迹上的reverse-KL探针，不代表实际Top10 CE的训练信号；对H4，它们只描述
OPD分支，不包含真实标签CE分支。不能据此推断H3或H4的总梯度仍然稀疏。

更新诊断在步骤1/5/10/15/20对相同原始token再做一次更新后forward。
令 d=log p_after−log p_before，记录 sampled old-policy KL 与非负k3代理 exp(d)−1−d；
同时保留按 sampler→learner ratio 加权的版本。它们不是更新后的 teacher KL，
也不构成整条轨迹分布的精确KL。importance ratio 接近1主要检查采样器与更新前模型的一致性。

Top10训练只在诊断步骤额外记录 sampled KL；本地审计还从所有原始采样/teacher概率
重算全程KL，并区分全量、日志采样和匹配诊断步骤的覆盖。Top5%信号占比先在各batch内
计算，再按batch信号总量加权，不冒充全程所有token的global top5%。混合或无法精确对齐的
token分类为 `unknown`；高unknown覆盖时不能据此判断数字与HTML标记谁占主导。

| 方案 | 全程采样reverse-KL | 更新k3代理 | 近零advantage比例 | batch内Top5%信号占比 | 梯度范数>1的步数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Control160 | 0.04307 | 0.002263 | 80.1% | 96.1% | 3/20 |
| H2 | 0.04243 | 0.000517 | 78.8% | 93.2% | 4/20 |
| H3 | 0.04842 | 0.001511 | 67.8% | 85.5% | 0/20 |
| H4 | 0.04579 | 0.002309 | 78.4% | 94.8% | 2/20 |

全程reverse-KL从所有原始轨迹重算；k3与信号分布来自同样5个诊断步骤，按completion
token加权（Top5%按信号总量加权）。近零阈值为|advantage|≤0.001。
所有20步均实际返回梯度范数；每组5次更新后诊断均可从原始概率重算。
unknown类别覆盖约72–78%，所以本轮不对数字/标记的梯度主导关系作归因。

H2的更新k3约比Control160小77%，并伴随Train/Dev/Test似然和Cell F1改善，支持降低
更新幅度；但它并没有更少的梯度超阈值步骤。H4的更新k3与Control160接近，却显著改善
真实标签似然及Test内容质量，支持目标对齐这一方向。H3没有出现大梯度范数，仍有严重
截断，因此不能把所有问题都归结为梯度爆炸。小KL、低NLL和低梯度范数都不是生成正确的保证。

下一步优先在相同Train800协议下复验较低LR；有真实标签时再独立验证混合目标。
本轮没有测试“低LR+Gold”组合，也没有加跑新的Train800。Top10路线应先定位重复和
终止行为，不建议仅增加输出上限后直接扩大训练。

## 证据和局限

图片、标签、原始轨迹、概率数组、checkpoint地址和真实路径不提交Git、不上传W&B；
运行所需图片和训练目标仍由Tinker处理，本地实验记录保存在忽略目录。
W&B只接收允许的汇总指标与配置；公开文档只给出统计量。共享预算在每次新操作前预留，
成功后核验完成报告与哈希，再按实际记录的token费估算结算。异常操作不自动重跑optimizer。

这是单个训练seed、Train160规模的机制实验。固定Test100已经反复用于迭代比较，
不是从未查看的最终留出集；候选配方、checkpoint和多个指标也带来多重比较问题。
本轮可以提供下一步方向，不能证明原OPD800未超过KD800只有一个根因，也不能保证
把同一处理放大到Train800后会得到相同收益。
